## Runbook and input contract

1. Qualify a consistent source. Reconcile its 30 stable security IDs, corporate actions, venue, and price and volume adjustment semantics with the training archive. Demonstrate final daily releases between the Nasdaq signal close and the following session open, with verifiable publication and retrieval timestamps. Use a separate readiness JSON and adjacent `source_evidence.md`. The JSON must say `status=approved`, contain the evidence SHA-256, and declare `source`, `adjustment_policy`, and `security_ids` mapping every cohort ticker to a stable instrument ID. This is an explicit source-review gate. The runner verifies the evidence bytes and consistency of manifests. It cannot authenticate a provider's factual claims or timestamps.
2. Produce a Parquet with exact keys and columns `date,ticker,open,high,low,close,adj_close,volume`. Issue uses 61 complete sessions through the signal close. Settlement uses exactly the signal and target sessions from the same adjustment vintage. Each Parquet has a JSON metadata sidecar with the same source, adjustment policy and ID mapping, plus `revision`, `published_at`, `retrieved_at`, and `sha256`. Preserve original delivery and release evidence. Metadata timestamps must carry an explicit timezone.
3. Run `.venv/bin/python -B -m experiments.prospective_cohort_v1.live issue --day YYYY-MM-DD --gate GATE.json --bars BARS.parquet --meta META.json` after the signal close and before the next open. The timezone-aware NASDAQ calendar handles holidays and early closes. The runner requires a close after the freeze and uses the actual system clock. It rejects incomplete days, bad data, mismatched hashes or future bars. Each dated issuance is written as an atomic exclusive file with verified input bytes stored by hash. The process is manual and no background schedule was installed.
4. Run the same command with `settle` and the settlement inputs after the exact next trading session closes. Settlement writes a separate exclusive record linked to the prediction hash. Missing or invalid endpoint data means the date remains unsettled. To establish independently auditable ordering, retain the published file digest in an external timestamped append-only system before the next open. Local files and timestamps protect against routine rewrites by this runner. They do not prove tamper resistance against the machine owner. The workflow supplies no external timestamping service.
5. Run `.venv/bin/python -B -m experiments.prospective_cohort_v1.live evaluate`. Results include number of settled sessions, stock-day count, accuracy, matched majority, MCC, balanced accuracy, precision, recall, F1, positive and negative call counts, raw within-day AUC and corresponding selective figures. Uncertainty for accuracy, excess over majority and AUC uses 10-session date blocks once at least 10 sessions are settled. Within-day AUC requires both realized classes on a date. Report missed issuance dates and incomplete settlements alongside metrics during the live study to expose possible coverage bias.
